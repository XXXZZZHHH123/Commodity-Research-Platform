# 大宗商品研究工作台 · 一期开发计划（锡 / SN）

## Context

研究员的判断现在活在一份静态 prompt 里，三个具体的痛点已在锡的实战中被验证：判断会过期而没人知道（TC 从 17,500 涨到 18,000、价格已破 40 万仍在按旧阈值比对）、数据靠手工且口径靠记忆（主力连续价与合约价混用会让基差从贴水变升水）、判断无法被检验（没有任何地方记录"当时的判断是什么、后来对不对"）。

一期要把锡的研究判断从静态文档变成一个**可录入、可自动比对、可每日查看**的活对象，跑通"判断录入 → 自动取数 → 阈值监测 → 看板与日报"的最小闭环。

**这个系统的工程本质是三条不变量**，其余都是外围：
1. 任何数字都带口径 `caliber` 与数据时点 `as_of`（P2）
2. 派生计算在口径/时点不一致时**输出阻断状态，而不是一个看似正常的数**（FR-5.2）
3. 每条证伪条件必须绑定一个可自动采数的指标（P3）

平台不产生判断——这是 P1，要靠代码结构保证，不靠约定。

**起点**：项目目录为空（仅有空的 `PRD/`）。绿地项目，从零搭建。

## 六个里程碑

### M0 · 走通一条链路（第 1–2 周）　✅ 2026-09-18 完成

目标：研究员第 2 周就能看到真东西。直接对冲 R1「研究员不用」这个最大风险。

- **Day-1 技术探针（前置，见下方风险）**：验证 akshare 的沪锡行情/库存/仓单接口当前可用性与字段口径
- Alembic 建全表（04 §1 全部，含 factors / judgment_factor_link / macro_scenarios 预留字段，避免三四期迁移）

- SHFE 采集器 → `observations`，强制带 `caliber`/`as_of`/`fetched_at`/`source`/`source_url`
- **一条公式 `BASIS` + 同时点守卫**：现货人工录入 vs 期货自动取数，演示阻断
- 品种页「区域 C 六个核心数字」+ 就地展开看输入与时点
- JSON 快照导出（04 §1.9 结构）

> 验收：人为制造时点错配（用前一日现货价配当日期货价）→ 页面出「口径不一致，故不计算」并列出冲突的两个输入及其时点，**不出数**。

### M2 · 判断层（第 4–5 周）

- 九字段表单，分段独立保存 + 草稿自动留存（I3）

## 几个关键设计决定

1. **同时点守卫放在计算层唯一入口**（`compute/guards.py`），不散落在各公式里。公式只声明所需 `price_type` 与时点容差。
2. **阻断时 `derived.value` 写 NULL**，让"看似正常的假数"在数据库层面就不可能存在。
3. **`observations.caliber_snapshot` 存入库时的口径快照**，口径字典日后修订仍可追溯。
4. **judgments 按整份快照 + version 自增存储**，diff 在读取时计算——符合"判断是一份带时间的快照"的语义，也让任意两版对比天然成立。
5. **`signals` 没有"建议"字段，一期 `confidence` 固定 100**（规则判定）。平台不输出方向——P1 在数据模型层面就被钉死。
6. **合规红线硬编码**：一期代码中不存在任何 SMM / LME / Mysteel 的抓取入口。这三家的数据（现货价、社会库存、TC、LME 库存、开工率）全部只能走人工录入通道。

## 验证方式

**自动化测试**（pytest）：
- 同时点/口径守卫：容差内外、缺输入、口径冲突四类用例
- 8 个公式的数值正确性与阻断行为
- 判断状态机流转、三条强制校验、审稿清单五项触发条件

**端到端验收**——逐条对应 01 §7.1 的十项勾选：
1. 把《锡_研究逻辑.txt》全文导入，逐字段比对无丢失
2. 造一条未绑定指标的证伪条件 → 提交被拒
3. 造两条阈值但不填优先级 → 提交被拒
4. 页面展开基差/跨期价差 → 看到输入指标与各自时点
5. 用前一日现货价配当日期货价 → 不出数并提示原因
6. 让某指标断更 → 品种页出数据缺口，且不显示旧值、不显示 0
7. 把复核周期设成 1 天 → 次日全站出"已过期"
8. 手工造一次"连续两期累库" → 触发证伪并生成待确认事项
9. 校验当日 JSON 快照含 judgment / observations / derived / signals / gaps
10. 报告归档页按历史日期翻页

**手工验证**：`uvicorn` 起服务后在浏览器实走一遍研究员的早晨动线——登录直达锡的今天，5 秒内看清判断状态、触发信号、六个核心数字。

### 对 PRD 的发现（需研究员 / 产品确认）

1. **上期所盘后数据没有“最新价”**，只有收盘价与结算价。04 §1.10 示例的 `.last` 不适用于盘后采集，序列按实际口径命名为 `.close` / `.settle`。
2. **上期所每日只发布注册仓单，交易所库存是周报**。04 §2 的 `SHFE.SN.stock.daily` 不存在；01 §4.2 首屏的“SHFE 库存及日变化”实现为“注册仓单及日变动”，周库存另登记为 `SHFE.SN.stock.weekly`，不与日频仓单同屏（遵循 01 §4.6“同页只显示一个时点的库存”）。
3. **口径字典新增两个枚举值**（W1 定稿时请研究员确认）：合约标识 +“主力合约”（本平台按持仓每日选出、可追溯到具体合约，区别于数据商拼接的“主力连续”）；库存范围 +“交易所注册仓单”。
4. **新登记 `MACRO.SPX`**：04 §2 未列，但锡判断的定价权与风控线都引用了 SPX（白名单拉动底座扩张，00 §4）。
5. **取数失败不写入 observations**：04 §1.2 设想用 `status=缺失` 的行表示失败；改为记入 `fetch_runs`，observations 只存真实取到的数，避免任何查询漏过滤而读到空值行。
6. **锡判断 v1 目前无法生效**，缺的正是 FR-1.3 引用的那个例子：VIX>19 风控线（降敞口）与 40–41 万介入位（回调做多）可能同时触发，原文没有优先级。另有三条原文无法自动化，已原样保留并注明原因：“SPX 破 20 日线”（无均线序列）、“风控红线② SOX”（无触发水平）、证伪“40 万附近成交放量”（“附近”“放量”未量化）。
7. **审稿清单（M2）上线后会对 v1 报警**：定价权声明的 SOX / SPX / VIX 均不在白名单内（FR-1.6“白名单与定价权脱节”）；TC 17,500 未注明数据时点，且 00 §2 称已升至约 18,000。

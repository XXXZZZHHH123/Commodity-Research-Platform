# 二期 · 模板工具与扩面

> 版本 v1.0 ｜ 2026-09-18 ｜ 上级文档 `00_总控.md`
> 本文是**规划**，不是 PRD。进入开发前需先完成 §8 的待验证问题，再据此写二期 PRD。

---

## 1. 二期目标

从"锡能用"到"别人也能用"。

一期证明了一个品种的判断可以被结构化、被监测。二期要证明的是：**这套结构不是为锡定制的，而是研究总纲方法论的通用载体**，其他金属品种的研究员能照着写出自己的判断单元。

**验收标准（唯一）**：另一位金属研究员独立录入一个品种的完整判断，全程未询问我们怎么填。由锡的作者本人录第二份不作数。

## 2. 通用模板工具

一期的判断表单是"锡能用的表单"，二期要把它变成"任何品种都能用的模板"。

### 2.1 字段抽象

一期九字段来自研究总纲的目录树模板，本身已是通用设计。二期要处理的是字段内部的品种差异：

| 差异点 | 锡的情况 | 抽象方式 |
|---|---|---|
| 边际定价权的候选项 | 宏观（SOX/SPX）+ 矿端事件 | 做成可配置枚举：有 LME 外盘 / 纯宏观 / 无外盘；各自带典型来源清单 |
| 成本线类型 | 冶炼 TC + 下游传导率 | 按板块给不同的成本线模板（有色看现金成本与边际产能，能化看成本定价公式） |
| 编排范式 | 总线合成 | 三选一，选择后影响 agent 侧的调用方式 |
| 白名单指标数量 | 5 个 | 保持 3–8 个约束，但允许按板块给推荐清单 |

### 2.2 样板与指引

- 新建判断时，默认加载**锡的完整示例**作为参考（只读对照，不预填内容）
- 每个字段旁提供一句填写要领与一个正例、一个反例
- 反例取自我们已发现的真实问题（只填单边的主逻辑、无法验证的证伪条件、只有绝对值没有方向的指标）

### 2.3 审稿清单升级

一期的审稿清单是硬编码检查项，二期做成可配置规则集，并新增：

- 主逻辑的验证窗口是否已过期
- 阈值之间是否存在逻辑矛盾（如介入位高于风控减仓位）
- 白名单指标是否长期无数据（登记了但取不到）
- 同一板块内，本品种的宏观假设是否与其他品种冲突（三期联动的前置）

### 2.4 模板版本管理

模板本身需要版本：模板升级时，已有判断单元不强制迁移，但在页面提示"当前模板已更新至 vX，本判断基于 vY"。

### 2.5 协作

- 判断单元有明确 owner；他人可评论，不可直接修改
- 评论与回复记录在版本历史中（研究讨论的痕迹本身有价值）

## 3. 扩面

### 3.1 订阅接口接入

前置：知几 API 的可用指标清单、频率、配额、历史回补能力（总控待决事项 #2）。

目标指标：锡锭社会库存、云南 40% 锡精矿 TC、焊料开工率、ICDX 成交量、LME 锡库存。这五项正是现有锡 prompt 的白名单，一期靠人工录入，二期转自动。

### 3.2 海关适配器

若一期采用人工月度导出，二期转为适配器，并扩展到其他品种的 HS 编码。

### 3.3 新增 2–3 个金属品种

选择标准：与锡指标重合度高、研究员愿意配合。铜、铝、锌为候选。

**衡量指标**：新增第二个品种时，新登记指标的比例应低于 40%；若高于此，说明底座抽象不足。

## 4. 调研信息差模块

一期为自由文本，二期结构化。字段直接对应总纲的调研四问：

| 字段 | 必填 | 说明 |
|---|---|---|
| 结论 | 是 | 调研得到的结论本身 |
| 立场 | 是 | 谁说的、他的利益方向 |
| 样本 | 是 | 问了几家、什么类型 |
| 时点 | 是 | 调研发生时间 |
| 价格是否已反映 | 是 | 是 / 否 / 未知 |
| 跟踪指标 | 否 | 用哪个已登记指标验证 |
| 失效日期 | 是 | 超期后自动降权并提示复核 |

**用途**：调研结论是"假设发生器"，不是结论。系统的职责是提醒研究员这条假设该验证了，而不是把它当事实使用。

## 5. 告警推送

- 渠道：企业微信或飞书机器人
- 触发类型：证伪条件触发、风控阈值触发、判断到期、核心指标断更
- 频控：同一条件 24 小时内只推一次；每日汇总一条
- 订阅粒度：按品种订阅，研究员默认订阅自己的品种

## 6. agent 接口

### 6.1 MCP 服务

工具粒度建议：

| 工具 | 输入 | 输出 |
|---|---|---|
| `get_variety_snapshot` | 品种、日期 | 当日完整数据包（见一期 JSON 结构） |
| `get_judgment` | 品种、版本（可选） | 当前或指定版本的判断单元 |
| `get_series` | series_id、区间 | 时间序列，带口径与来源 |
| `list_signals` | 品种、日期区间 | 触发记录 |

### 6.2 协议对齐

输出字段与研究总纲的【标准化摘要】保持一致：Agent 名、核心信号、影响方向、可信度 0–100、核心结论、关键证据、主要冲突、数据缺口、后续验证。

### 6.3 写作规则

晨报生成遵循总纲的去 Agent 化要求：成文中不出现"某某 agent 认为"之类表述；所有数字保留证据链接。

## 7. 内容模块

| 模块 | 说明 | 复用方式 |
|---|---|---|
| 新闻聚合与早班车 | 多源 RSS 抓取、去重、时间窗分级（24h 全留 / 24–72h 仅高影响）、源配额、AI 摘要、品种标签 | 开源日报框架换源清单即可，不自研 |
| 事件日历 | 交割日、节前保证金调整、海关与统计发布日、FOMC | 交易所公告 + 固定日程 |
| 周报 | 按周汇总判断变化、信号触发、关键数据 | 复用一期日报模板 |
| 图表实验室 | 任选指标组合作图，供研究员探索 | 二期后段 |

**注意**：情绪标注（利多/利空/中性）若做，必须先验证分类准确率；参照对象的情绪分布是 185 条里 180 条中性、0 条利空，等于没有信息量。宁可不标。

## 8. 待验证问题（进二期 PRD 前必须有答案）

| # | 问题 | 验证方式 |
|---|---|---|
| 1 | 第二位研究员是谁，他愿意投入多少时间 | 直接沟通 |
| 2 | 他现有的研究框架与总纲模板差多远 | 让他用纸笔按九字段写一遍，看卡在哪 |
| 3 | 知几 API 能否覆盖五个白名单指标 | 技术验证 |
| 4 | 新品种的指标重合度 | 用铜做一次纸面推演 |
| 5 | 成本线模板是否需要按板块分化 | 与两位研究员核对 |
| 6 | 告警推送的频次上限，多少条会让人开始忽略 | 一期末尾问研究员 |
| 7 | agent 侧现有 prompt 改造成本 | 拿现有锡 agent 试接 JSON 快照 |

## 9. 二期风险

| 风险 | 应对 |
|---|---|
| 第二位研究员不配合 | 二期无法验收。应在一期末尾就确认人选，不要等开发完再找 |
| 模板过度抽象，变得谁都不好用 | 抽象只做到板块级，不追求 77 品种一套表 |
| 订阅接口配额不足 | 保留人工录入通道，不下线 |
| 新闻模块喧宾夺主 | 明确它是佐料：新闻不进入阈值判定，只作为信号的背景说明 |

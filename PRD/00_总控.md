## 1. 一页纸

**这是什么**：一个把研究员的判断、可自动获取的数据和 agent 的执行能力接成闭环的内部工具。研究员把判断写进去（主逻辑、阈值、证伪条件），平台每天自动取数、比对、告警，agent 基于同一份数据和判断产出晨报，所有结论都能点回原始数字。

**这不是什么**：不是行情站（公开行情站已经够用且免费），不是研报库，不是给管理层看的填报系统。

**一句话定位**：平台不替研究员判断，但它保证判断被诚实执行、被事后检验、并被持续供给更好的原料。

**一期范围**：以锡为例，跑通"判断录入 → 自动取数 → 阈值监测 → 看板与日报"的最小闭环。

---

## 2. 背景与问题

现状有三个具体痛点，都在锡的实跑中被验证过：

**问题一：判断会过期，且没人知道它过期了。**
锡研究逻辑 prompt 写于 2026-08-16，其中的价格锚、阈值、TC 数值均为当时快照。一个月后价格已跌破 40 万介入位、TC 从 17,500 升至 18,000 左右，但 prompt 没有复核机制，agent 继续拿过期阈值做比对。

**问题二：数据靠手工，口径靠记忆。**
研究员手工抄数、手工算基差与月差。同一页面上主力连续价、主力合约最新价、前一交易日收盘价混用，会让基差从贴水变成升水，结论直接反向。这类错误无法靠细心避免，只能靠机制避免。

**问题三：判断无法被检验。**
现有流程里没有任何地方记录"当时的判断是什么、后来对不对"。TC 方向读反这类前提性错误，会被 agent 沿着错误前提放大，而不会被发现。

## 3. 产品原则

| # | 原则 | 含义 |
|---|---|---|
| P1 | 平台不产生判断 | 事实层与判断层严格分离。平台可给通用信号，但不与研究员的品种判断加总 |
| P2 | 事实必须带口径与时点 | 任何数字都携带口径、数据时点、来源、原始链接；口径或时点不一致时拒绝计算，而非给出一个看似正常的错数 |
| P3 | 判断必须可证伪 | 每条证伪条件必须绑定一个可自动取数的指标；绑不上的证伪条件退回重写 |
| P4 | 只展示必要元素 | 凡是不能回答"看了它我会做什么"的元素，不进首屏 |
| P5 | 低摩擦 | 打开即用、分段保存、下拉选择、就地展开、一键导出 |
| P6 | 先对录入者有用 | 前三期所有功能围绕"对研究员本人有用"设计。管理层视图放第四期 |

## 4. 三层结构

```
┌──────────────────────────────────────────────────────┐
│ L3 跨品种与宏观层                                      │
│    共享驱动因子 / 比价与相对强弱 / 判断冲突检测         │
│    宏观情景 → 品种依赖声明 → 批量复核提示               │
├──────────────────────────────────────────────────────┤
│ L2 品种判断单元（一个品种一个，可版本化）               │
│    主逻辑 / 边际 / 成本线 / 定价权 / 时间维度 /        │
│    调研信息差 / 指标白名单 / 编排范式 / 基调            │
│    + 阈值集 + 冲突优先级 + 证伪条件                    │
├──────────────────────────────────────────────────────┤
│ L1 事实底座（只存事实，不产生判断）                     │
│    观测 observations / 派生 derived / 指标登记表        │
│    口径字典 / 证据链 / 同时点校验                      │
└──────────────────────────────────────────────────────┘
```

**底座宽度的扩张方式**：不按覆盖率扩，按白名单拉动扩。某个品种的判断单元里写了某个指标，这个指标才进底座。没人用的指标不接。

## 5. 六个功能域 × 四期

| 功能域 | 一期（锡跑通） | 二期（模板与扩面） | 三期（联动） | 四期（宏观与治理） |
|---|---|---|---|---|
| **A 判断层** | 判断录入表单 v1（九字段、双向对立校验、优先级必填、证伪绑定指标）、锡判断录入、版本记录与 diff、审稿清单 | 通用模板工具、模板版本管理、协作与审稿流、调研信息差模块 | 判断间依赖声明 | 模板扩展到非金属板块 |
| **B 事实层** | 指标登记表、口径字典、免费源自动取数、人工录入通道、派生计算与同时点校验 | 订阅接口接入（社库/TC/开工率）、海关适配器、扩到 2–3 个金属品种 | 共享因子表、比价与内外盘同口径处理 | 宏观变量库、regime 定义 |
| **C 监测层** | 阈值与证伪自动比对、判断到期提醒、触发记录 | 告警推送（企微/飞书）、数据缺口告警 | 共享因子异动触发跨品种复核、白名单外盲区扫描 | 宏观情景变化触发批量复核 |
| **D 展示层** | 品种页、判断页、指标管理页、日报归档页、每日快照导出 | 周报、图表实验室、新闻聚合、事件日历 | 板块视图、强弱排序、判断冲突看板 | 管理层视图、命中率复盘页 |
| **E 联动层** | — | — | 共享驱动因子、比价与相对强弱、判断冲突检测、合成层 | 宏观到品种自动推送、regime 动态权重 |
| **F 治理与接口** | 登录、操作留痕 | agent 接口（MCP）、标准化摘要协议对齐 | 合成层称重与观点稳定性约束 | 权限分级、审计、决策层台账与每手风险 |

## 6. 每期验收标准（行为变化，不是功能清单）

| 期 | 验收标准 |
|---|---|
| 一期 | 研究员不再手工抄一期覆盖的那几个数；锡的判断在系统里有版本记录；证伪条件触发时，她在自己发现行情变化之前先收到提示。反例：上线后她仍打开 Excel 抄数 → 本期失败，无论交付了多少功能 |
| 二期 | **另一位金属研究员独立录入了一个品种，全程未询问我们怎么填。** 这是模板可用性的唯一判据；由锡的作者本人录第二份不作数 |
| 三期 | 板块会上出现过至少一次这样的讨论：平台提示两个品种对同一宏观情景的假设相反，两位研究员就此对话 |
| 四期 | 能用数据回答"过去半年的判断里，哪些阈值真有预测力" |

## 7. 全局约束

### 7.1 数据合规三红线

1. **授权数据不落到公开可访问的页面。** LME 价格与库存属授权数据，内网展示与再分发均需先确认现有合同条款。
2. **订阅数据不绕接口抓取。** SMM 明确声明未经书面同意不得以任何形式复制其内容（含单个价格、图表、新闻）。社库、TC、焊料开工率一律走公司已订阅的接口。
3. **复用同事既有成果需书面授权。** 参照仓库 `gsy1005/tin-research` 的许可为"保留所有权利，仅供授权对象内部参考"。本项目**不复用其代码**，仅参考其研究逻辑与指标选择，并需就方法论模板化一事取得作者同意。

### 7.2 口径与时点规则（P2 的工程落法）

- 所有观测入库必须带 `caliber`（口径）与 `as_of`（数据时点）。
- 派生计算必须声明输入指标与时点容差；超出容差不出数，状态标记为 `blocked_timestamp_mismatch`，页面显示拦截提示。
- 页面上每个派生值旁显示其使用的时点。

### 7.3 角色边界

**平台负责事实，agent 负责论证，研究员负责判断。**
平台不输出方向；agent 不修改判断；研究员不手工抄数。

## 8. 技术栈方向

| 层 | 选型 | 说明 |
|---|---|---|
| 采集与计算 | Python | 公开数据用 AKShare（MIT、免 Key、覆盖期货行情与库存周报），订阅数据走公司内部接口 |
| 存储 | PostgreSQL（IT 资源紧张时一期可用 SQLite + 每日备份） | 见 `04_附录` 数据模型 |
| 调度 | 内网 cron 或 Airflow | 每日收盘后与次日早间两次 |
| 前端 | 静态页面 + 图表库，无框架 | 一期不做前端框架选型 |
| agent 接入 | MCP 服务（二期） | 工具粒度：取某品种某日数据包、取某品种当前判断 |
| 部署 | 内网优先 | 数据含订阅与授权内容，公网托管触碰 7.1 红线 |

## 9. 风险登记

| ID | 风险 | 影响 | 应对 | 责任 |
|---|---|---|---|---|
| R1 | 研究员不用 | 最大风险，平台沦为摆设 | 一期只做她现在手工做的事且做得更快；上线前让她参与定义品种页布局与口径字典 | 产品 |
| R2 | 授权未落实 | 无法复用现有成果，可能引发内部冲突 | 立项时谈妥授权范围、角色、成果归属 | 项目发起人 |
| R3 | 订阅接口不可用或配额不足 | 社库、TC 缺失，判断层一半失效 | 一期不依赖订阅接口，用人工录入通道兜底；并行确认知几 API 清单与配额 | 产品 + IT |
| R4 | 海关适配器维护 | 平台改版即断供 | 保留人工月度导出作为降级预案 | 研发 |
| R5 | 判断录入成本高 | 研究员嫌麻烦，判断快照形同虚设 | 提供从现有 prompt 文本导入的能力，先导入再修订 | 产品 |
| R6 | 模板导致形式主义 | 为填满字段而编字段 | 允许"不适用 + 理由"；质量看证伪条件能否绑定数据，不看填写完整度；完整度不得进入考核 | 产品 |
